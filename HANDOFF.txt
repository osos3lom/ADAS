 WHAT WAS WRONG IN THE REPO (root-cause of the rebuild)
===============================================================================
Every backend Python file AND every Docker/deploy config file had been committed
TRUNCATED to exactly 512 characters (cut off mid-statement) in commit 98a5bd0.
They were not valid Python and the backend could not even import/boot. There was
no un-truncated version anywhere in git history.

The FRONTEND was fully intact. The corrupt Python files were incomplete ports of
the TypeScript in frontend/lib/, so the backend was rewritten 1-to-1 FROM that
intact TS reference:
  frontend/lib/scenarios.ts        -> backend/simulation/{state,scenarios,engine}.py
  frontend/lib/uds-processor.ts    -> backend/uds/{constants,services,processor}.py
  frontend/types/index.ts          -> backend Pydantic models (camelCase aliases)

===============================================================================
 HOW TO RUN
===============================================================================
Docker (both services):
    docker compose up --build
    dashboard  http://localhost:3000     backend  http://localhost:8000 (/docs)

Backend only:
    cd backend
    python -m venv .venv && .venv\Scripts\activate   (Linux: . .venv/bin/activate)
    pip install -r requirements.txt
    uvicorn main:app --reload --port 8000
    pytest

Frontend standalone (TS mock, no backend):
    cd frontend && npm install && npm run dev

Frontend against backend:
    set BACKEND_URL=http://localhost:8000   (PS: $env:BACKEND_URL="...")
    npm run dev

   (Resolved: renamed to backend/canbus/.)

 * AEB scenario note: the AEB "active" DTC (P1001) emission is gated on narrow
   time windows AND a TTC<=1.5 condition that rarely align at ~0.5s poll cadence
   (faithfully ported from the TS). Tests therefore assert on the DETERMINISTIC
   sensor-fault DTC (B1001) instead. Revisit gating when the real ROS2 planning
   FSM is built in Phase 2.
