TRUNCATED to exactly 512 characters (cut off mid-statement) in commit 98a5bd0.

 HOW TO RUN
===============================================================================
Docker (both services):
    docker compose up --build
    dashboard  http://localhost:3000     backend  http://localhost:8000 (/docs)

Backend only:
    cd backend
    python -m venv .venv && .venv\Scripts\activate   (Linux: . .venv/bin/activate)
    pip install -r requirements.txt
    uvicorn main:app --reload --port 8000
    pytest

Frontend standalone (TS mock, no backend):
    cd frontend && npm install && npm run dev

Frontend against backend:
    set BACKEND_URL=http://localhost:8000   (PS: $env:BACKEND_URL="...")
    npm run dev

===============================================================================
 KNOWN ISSUES / FOLLOW-UPS
===============================================================================
 * SECURITY: next@15.3.3 has a known CVE (CVE-2025-66478). Upgrade Next.js
   (and recharts 2.x is deprecated). Do an `npm audit` pass.
 * frontend/package-lock.json IS now committed (generated this session). CI
   still uses `npm install` with npm caching disabled; you can switch CI to
   `npm ci` + enable setup-node npm caching now that a lockfile exists.
 * backend/ package named `can/` will SHADOW the PyPI `python-can` module when
   real CAN is wired in Phase 3. Rename it (e.g. `canbus/`) at that point.
   (Noted in backend/can/__init__.py.)
 * `next build` auto-edited frontend/tsconfig.json (added target ES2017) — kept.
 * AEB scenario note: the AEB "active" DTC (P1001) emission is gated on narrow
   time windows AND a TTC<=1.5 condition that rarely align at ~0.5s poll cadence
   (faithfully ported from the TS). Tests therefore assert on the DETERMINISTIC
   sensor-fault DTC (B1001) instead. Revisit gating when the real ROS2 planning
   FSM is built in Phase 2.
